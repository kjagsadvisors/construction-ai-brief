# Pillar templates

Five pillars. Every published piece maps to exactly one. The drafter receives
the matching template inline with the system prompt.

---

## 1. tool_teardown

**Format:** 1500-2500 words. Newsletter Thursday slot (rotating).

**Structure:**
1. Opening — name the tool, name the specific workflow, name the contractor type who'd care.
2. **H2: what it actually does.** Plain-language teardown. No vendor copy.
3. **H2: where it works.** Specific use cases with named workflows.
4. **H2: where it doesn't.** Honest limits. What still needs a human. What edge cases break it.
5. **H2: the math.** Pricing, expected ROI, what to compare against (status quo / competitor).
6. **H2: who should evaluate this.** Which segment, what shop size, what existing stack.
7. **H2: how to pilot it in 2 weeks.** Concrete steps. Names exact workflows to test against.
8. Closing CTA — role-matched.

**Sources required:** vendor docs, ≥1 third-party review or case study, ≥1 hands-on or public pricing reference.

---

## 2. punch_list

**Format:** 600-900 words. Tuesday newsletter.

**Structure:**
1. Opening paragraph — week's theme, 2-3 sentences, no fluff.
2. **5-7 numbered items.** Each item: headline (1 line), 2-3 sentences of "why this matters to a contractor", source link.
3. Items cover: new tool launches, funding rounds when relevant, regulatory moves, useful research, public failures or honest postmortems.
4. **Last item** is always a "tool to evaluate this week" — links to a tool_teardown if we have one.
5. Closing CTA — generic for that week's dominant audience tag.

**Sources required:** ≥1 cited URL per item.

## 3. playbook

**Format:** 1200-2000 words. Thursday newsletter (rotating).

**Structure:**
1. Opening — the specific problem, the specific role who has it, the specific stack involved.
2. **H2: the problem on Monday morning.** Concrete workflow being broken or slow.
3. **H2: what you'll build / set up.** Architecture diagram in ASCII or named tools.
4. **H2: step-by-step.** Numbered, ≥5 steps, each step with what to do + why.
5. **H2: where it breaks.** Failure modes, edge cases, what to watch for.
6. **H2: what to add next.** Optional extensions.
7. Closing CTA.

**Sources required:** any tool referenced has a link; any prompt template included is full.

---

## 4. field_report

**Format:** 1000-1800 words. Thursday newsletter (rotating).

**Structure:**
1. Opening — name the shop type (e.g. "a 50-person mech contractor"), the workflow they fixed, the rough outcome.
2. **H2: the starting state.** What was broken. Hours per week wasted. People affected.
3. **H2: what they tried first.** Almost always — software they bought that didn't work, or a hire that didn't scale.
4. **H2: what actually moved the needle.** The specific change. Tooling, process, people.
5. **H2: the numbers.** Hours saved, dollars saved, error rate change. Sourced where public.
6. **H2: what they'd do differently.** Honest.
7. Closing CTA.

**Sources:** if anonymized (default), state the anonymization rule; if named, link to public talk/podcast/press.

---

## 5. trend

**Format:** 300-500 words + 1 chart. Friday newsletter "one chart".

**Structure:**
1. **The chart** (data + source + methodology line).
2. 2-3 short paragraphs — what it shows, what it means for a contractor, what to watch next.
3. One-line CTA.

**Sources required:** raw data file or scraped source must be linked. Methodology stated.
