Microsoft's new Decision-1 model does one narrow job: given a fixed list of choices, it scores each one so software can pick. For a GC, that points at the cheap, boring layer of an AI back office, the step that decides where an incoming RFI, submittal or pay app goes and whether an agent's next move needs a person. Cheap routing is useful. Letting a model decide what needs review is where a contractor should slow down.

## What did Microsoft release?

Per coverage of the October 9 launch, Decision-1 is a 9-billion-parameter model, reportedly post-trained from Alibaba's open-weight Qwen3.5-9B, now available in Microsoft Foundry with OpenRouter access said to be coming. It does not generate paragraphs. It takes a set of fixed answer options and returns a score for each.

Microsoft's stated uses are routing a ticket, checking an agent's proposed action, and deciding whether an agent should proceed, retry, escalate or ask for review. Reported details:

- **Price:** $0.042 per million input tokens, output tokens free.
- **Speed:** Microsoft says it is about 35 times faster than GPT-6 Sol at median latency.
- **Accuracy:** Microsoft says it ranked first across a 36-benchmark evaluation.
- **Stability:** Microsoft reports the decision changed 1.3% of the time on average when requests were perturbed, with no flips when options were reordered or reworded.

All of those performance numbers are Microsoft's. Reporting notes the announcement doesn't include the datasets or latency test conditions needed to reproduce them.

## What does this mean for a GC's back office?

The match is sorting work. A project inbox gets a stream of items that each belong in one of a handful of buckets, and today a project engineer or admin sorts them by hand.

| Task | Fixed options | Fit |
|---|---|---|
| Triage inbound email | RFI, submittal, change request, pay app, other | Good first test |
| Route a vendor document | Insurance cert, lien waiver, W-9, lead-time notice | Good first test |
| Check an agent's draft action | Send, hold, escalate | Use as a filter only |
| Approve a change order or pay app | Approve, reject | Do not delegate |

At a fraction of a cent per thousand items, the cost objection to running every email through a classifier mostly goes away. The question becomes accuracy on your documents, which no benchmark answers for you.

## What are the limits?

Reporting on the launch flags the main one: it is unclear whether the scores are calibrated well enough to set escalation thresholds safely. A model that says 92% on "proceed" is only useful if 92% means roughly nine in ten. If an agent's draft lien waiver gets a confident "send," the gatekeeper has just moved the risk, not removed it.

Two further cautions. A model scoring an agent's work is another model, with its own blind spots. And a fixed option list is only as good as the person who wrote it: if "escalate to the PM" isn't an option, nothing gets escalated.

## Should a mid-size GC act now?

Not by buying anything. Run a cheap, low-risk test:

1. Pull 200 past items from a project inbox that a person already sorted.
2. Run them through any classifier, Decision-1 included, against your bucket list.
3. Count misses, and note which buckets fail. Missed lien waivers matter more than missed newsletters.
4. Set the rule that anything touching money, schedule or a signature goes to a named person regardless of score.

The takeaway: cheap scoring models will make routing and first-pass checks nearly free, and approval authority stays a human, written-down decision.
