Anthropic now lets the small tools people build in Claude, such as a change order log, a crew hours tracker or a quick conduit fill calculator, install as standalone Mac and Windows apps. For a trade sub, that makes homemade tools easier to hand to the whole office. It also means an app nobody reviewed can, if someone allows it, run programs and delete files on that PC.

## What did Anthropic ship?

The beta, called "Install as app," [went live November 24](https://news.sulat.com/2026/11/25/claude-install-as-app/). You open an artifact in Claude Desktop, choose Install as app, and it shows up in a Claude Apps folder on a Mac or in the Start menu on Windows. Anthropic's [help article](https://support.claude.com/en/articles/18516354-install-an-artifact-as-an-app) lays out the rules:

| Item | What Anthropic says |
|---|---|
| Plans | Free, Pro, Max, Ultra, Team and Enterprise, rolling out gradually |
| Requirement | Claude for Mac or Windows, version 6.28899.0 or later |
| Default permissions | Whatever an artifact can do in a browser |
| App permissions (each needs Allow) | Notifications, keyboard shortcuts, floating over other windows (which reads cursor position), menu bar or system tray icon |
| Full access | Run programs and read, change or delete files without asking each time |
| Team plan | On by default. Full access off until an admin enables it |
| Enterprise plan | Off until an owner enables it under Organization settings > Artifacts |
| Review | "Anthropic doesn't review apps before you install them" |
| Not supported | Linux, web, mobile, HIPAA-ready organizations |

The installed app is a container, not a copy. [Unite.AI reports](https://www.unite.ai/anthropic-lets-claude-users-install-ai-built-tools-as-desktop-apps/) that edits by the owner or any other editor change the app for everyone using it, and requests it makes to Claude count against each user's plan limits.

## Why does this matter for a trade sub?

Most subs don't have an IT department. They have an office manager, a project manager who's good with spreadsheets, and maybe an estimator who has started building things in Claude. Those are exactly the people who will make these apps, and they'll make useful ones: a T&M ticket tracker, a submittal status board, a material takeoff helper.

Until now those tools lived in a browser tab. Making them desktop apps with notifications and shortcuts makes them feel like real software, and people will start to trust them like real software. Nobody has tested them like real software.

## What should the owner decide before people start installing?

1. **Check which plan you're on.** If the company uses Claude Team, installing is already on. If you're on Enterprise, nothing happens until an owner turns it on.
2. **Decide who can grant full access.** On Team it stays off until an admin enables it. Leave it off unless a specific app needs to touch files, such as one that renames scanned field tickets in a shared folder. Then turn it on for that reason, not by default.
3. **Treat every edit as a new version.** An "Allow" covers one version. Any update, even your own, asks again. Train people not to click Allow out of habit, because a tool on the accounting PC can change overnight if its builder edits it.
4. **Watch for outside code.** Anthropic's article warns that code an app loads from another website can change without a new permission request. If an app pulls from a site you don't control, it isn't really "your" app.
5. **Keep sensitive data out.** Installed apps aren't covered by zero data retention. Payroll, bid numbers and owner contract data shouldn't go through one unless your contracts allow it.

## What are the limits?

- **No field use.** It needs internet and a signed-in desktop session. It won't run on a tablet or phone, so it doesn't help a foreman in the field.
- **One owner, many users.** If the person who built the tool leaves or stops sharing it, the app stops working. Claude usually offers to uninstall it when an artifact is deleted or unshared.
- **Turning full access off doesn't undo anything.** Anthropic says revoking full access stops programs the app started but does not reverse changes it already made.
- **It's a beta.** Expect the rules above to change.

We've covered what goes wrong when homemade apps get shared without a review, after [24,664 Lovable-built apps were found exposing data with no login](/posts/2026-11-16-lovable-apps-24664-open-databases-construction-gc-ops-homemade-prequal-punch-list-apps-login-check). Desktop installs raise the same ownership question.

**Takeaway:** This week, have whoever administers your Claude account confirm the plan setting and keep full access off. Then make a one-line list of any app installed on office PCs, who built it, and who fixes it when it breaks. If an app doesn't have a name next to it, uninstall it.
