Anthropic said on August 25 that Claude's chat and its Cowork agent now run on one shared memory that updates while you're still talking, instead of summarizing a conversation only after it ends. For a construction team piloting AI on RFIs, submittal drafting, or contract review, that closes a specific, common complaint: today, every new chat or Cowork task starts from zero, and someone has to re-explain the project's spec format, the sub's scope, or the GC's submittal numbering before the tool is useful. It also opens a new question worth checking before anyone on the team turns memory on for anything involving money: what happens when two different jobs share the same account.

## What did Anthropic ship?

Cowork is Anthropic's agent product for knowledge work — instead of a back-and-forth chat, you describe a task and Cowork works through files, folders, and connected apps like Slack and Google Drive to produce a real output, citing back to the source documents. It requires a paid Claude plan and runs through the desktop app. Until this week, Cowork's memory and Claude's regular chat memory were separate systems. Anthropic's update merges them: a detail mentioned in a chat — say, that a project uses a nonstandard submittal template — is now available to a Cowork task assembling that submittal package, and vice versa. Memory also updates in real time as a conversation happens rather than waiting for the session to close, so switching between chat and Cowork mid-task no longer means repeating yourself.

## What's the actual construction workflow change?

This targets a friction that shows up any time a GC or sub tries to build a repeatable AI workflow around back-office paperwork. Procore's own pitch for its AI agent library, which added company-standard customization to its Submittal Review and RFI agents this summer, runs into the same problem from the other direction: someone still has to configure and re-confirm those standards. A general-purpose assistant with working memory reduces how often that setup has to happen — a project engineer who explained a job's RFI numbering convention in one chat shouldn't have to explain it again the next day in a different session.

## What's the new risk, and who should care?

The catch is what memory retains by default. Anthropic's privacy filter blocks a specific list of personal categories — health data, race, religion, political views, gender identity — from being stored automatically. It does not filter business data. Bid numbers, subcontractor pricing, and contract terms discussed in a chat are retained as memory the same as anything else, unless someone deletes them or turns the feature off for that conversation.

That matters most for estimators quoting two competing jobs, or PMs managing several clients, from the same Claude account. Without separation, there's a real path for pricing or scope language from one job's chat to surface, unprompted, in a completely different job's output.

The fix already exists in the product: Claude Projects, a feature for grouping related chats, gets its own isolated memory per project — details inside a Project don't leak into general chat memory or other Projects. Before piloting memory-on AI workflows for anything with dollar figures attached, set that up first:

| Do this | Not this |
|---|---|
| One Claude Project per job or client | One shared chat thread for everything |
| Delete or edit memories tied to a closed bid | Leave old bid data sitting in general memory indefinitely |
| Use incognito chat for one-off sensitive questions | Assume a "private" question isn't retained |

This is a narrower version of the [standing-access question the industry already ran into this week with OpenAI's and xAI's always-on agents](https://constructionaibrief.com/posts/2026-08-25-openai-xai-always-on-agents-construction-permission-risk) — whether an AI tool that remembers things keeps one client's information from bleeding into another's. Memory that carries forward useful project context is a genuine upgrade for a submittal coordinator or PM. Memory that carries forward a competitor's number into the wrong bid is not. The setup step that separates the two takes about five minutes per job.
