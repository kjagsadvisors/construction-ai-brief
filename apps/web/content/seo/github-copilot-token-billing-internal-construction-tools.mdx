If someone in your office used a GitHub Copilot seat to build an internal tool, such as an RFI-log watcher, a submittal tracker, or a vendor cut-sheet scraper, that tool no longer runs on a flat monthly fee. GitHub moved Copilot Chat, agent mode, code review, and the CLI to metered AI Credits on June 1, 2026; the promotional credit cushion on Business and Enterprise seats ended September 1; and the $10 Copilot Standalone seat announced October 28 includes no credits at all. The fix isn't to shut the tool off. Find out what it costs per month and put a hard cap on it before the next invoice.

## What actually changed in GitHub Copilot's pricing?

Per-seat subscription prices didn't move — Pro is still $10 a month, Pro+ is $39, Business is $19 per user, Enterprise is $39 per user. GitHub has since added a $100-a-month Max tier for individuals. What changed is what that seat price covers. Inline code completion and Next Edit Suggestions stay unlimited on every plan. Everything that does multi-step work — Copilot Chat, agent mode, code review, the Copilot CLI, and the cloud agent — now draws from a monthly pool of AI Credits billed at each underlying model's published API rate, with one credit worth $0.01. None of it rolls over to the next month.

Individual Pro and Pro+ have kept the same totals since launch: 1,500 credits a month for Pro, 7,000 for Pro+. GitHub's docs now split each into a fixed base and a "flex" allotment it says can change (Pro is 1,000 base plus 500 flex), so treat the flex portion as adjustable, not guaranteed. Business and Enterprise seats got a promotional cushion for the first three billing cycles: 3,000 credits per Business seat and 7,000 per Enterprise seat. It expired September 1, 2026, and those seats are now at the standard 1,900 and 3,900 credits per user. A firm running the same workload saw a second bill increase this fall with no change on its end.

## Why does this hit a construction office that doesn't employ developers?

Because you only need one person with a Copilot seat and the habit of reaching for agent mode. A lot of the small tools running inside GC and sub back offices, like an RFI-status watcher, a submittal-log monitor, or a spreadsheet cleanup script, got built that way: someone tried agent mode once, it worked, and it has run unattended since. Those workflows draw hardest on the metered pool, because agent mode makes many model calls per task and nobody watches each call.

## How much did costs actually jump?

Enough that GitHub's community forum filled with complaints after the first full cycle closed June 30. One developer logged a single agent-mode request burning 822 credits, 54% of a month's Pro+ allotment, on what they described as a small project. Outside reporting on that cycle described accounts projecting monthly bills jumping from roughly $29 to $750, and from $50 to $3,000, once usage was priced at metered rates. Code completion isn't the expensive part. Letting an agent run multiple steps unsupervised is.

## GitHub Copilot plans and AI credits, compared

| Plan | Monthly price | AI Credits included (as of November 2026) | Rollover |
|---|---|---|---|
| Individual Pro | $10/mo | 1,500 credits (1,000 base + 500 flex) | No |
| Individual Pro+ | $39/mo | 7,000 credits (3,900 base + 3,100 flex) | No |
| Individual Max | $100/mo | 20,000 credits (10,000 base + 10,000 flex) | No |
| Business | $19/user/mo | 1,900 credits/user, pooled (was 3,000 during the Jun–Aug promo) | No |
| Enterprise | $39/user/mo | 3,900 credits/user, pooled (was 7,000 during the Jun–Aug promo) | No |
| Copilot Standalone | $10/user/mo | None; metered from the first request | n/a |
| Copilot access via a GitHub Enterprise Cloud license | $0 seat charge | None; metered from the first request | n/a |

Code completion and Next Edit Suggestions are unlimited on every plan above and don't draw from the credit pool. Chat, agent mode, code review, the CLI, and the cloud agent all do.

## What changed in October 2026, and does the new $10 seat save money?

On October 28, GitHub announced that a GitHub Enterprise Cloud license now includes Copilot access with no separate seat charge, and that firms without that license can buy the same access as Copilot Standalone for $10 per user a month. The catch is in the billing docs: neither option includes any monthly AI Credits. Usage is metered from the first request against whatever budget the firm has set. The Enterprise-license route is open now only to customers working with a GitHub or Microsoft account team; GitHub says self-serve availability will come in stages. Existing Business and Enterprise seats are unaffected and still on sale.

For a small contractor's office, the math is simple. A $19 Business seat comes with $19 of pooled credits. A $10 Standalone seat comes with zero. Standalone is cheaper only for someone who uses under roughly $10 of Chat and agent work a month, and it removes the shared pool that lets a light user's unused credits cover the one person running an agent-built tool. If your office's usage is one heavy automation and four people who mostly use code completion, pooled Business seats are still the better fit. We'd only look at Standalone for seats that exist purely for completion.

One smaller date to know: GitHub's docs list a 30% discount on model costs for Copilot Fusion, its model-routing feature, through November 30, 2026, and don't say what follows. If a tool of yours routes through Fusion, expect its December cost to differ from November's.

## Can you cap the spend before it surprises you?

Yes, and GitHub has added more controls since the rough first cycle. The ones that matter for an office tool:

| Control | Where it applies | Hard stop? |
|---|---|---|
| Session limit (July 2026) | One Copilot CLI or SDK session | Soft; a request already in progress finishes first |
| User-level budget | One licensed user, covering pool and paid usage | Always |
| Organization, cost-center, or enterprise budget | Paid usage beyond the included pool | Only if "Stop usage when budget limit is reached" is enabled |
| Paid usage policy | Business and Enterprise accounts | Turning it off stops spending at the included pool; it is on by default |
| Automation limits (October 2026) | One Copilot Automation, per run or per day, week, or month | Yes; the run stops or new runs wait for the reset |

Two details in that table catch people. First, scoped budgets alert by default and keep billing; the stop option has to be switched on. Second, the paid usage policy ships enabled, so a firm that never opened its billing settings is authorized to run past its pool. If a user-level budget blocks someone mid-task, Business and Enterprise admins can now approve a budget increase request and restore access immediately, a feature GitHub made generally available on September 16.

None of these controls existed when the first billing cycle closed at the end of June, which is part of why that cycle caught so many users off guard. If your firm's Copilot seats are still running on default settings, this is the fix: open the Copilot billing and usage settings, check what's consuming the credit pool, give the person running the automation a user-level budget, and put a monthly limit on any scheduled automation before the next cycle closes.

## Should you keep the internal tool, rebuild it, or kill it?

That depends on what the tool is worth to your office, and metered billing gives you the first real number to compare against. Run one full billing cycle with a cap in place and look at the actual cost for your usage. If an RFI-log watcher costs $40 a month and saves a coordinator two hours a week, keep it. If a submittal-tracking automation burns hundreds of dollars because it re-scans every document on every run instead of only new ones, that's a design problem to fix before you judge the tool.

What still needs a person: someone has to own the tool, read the usage report each month, and decide whether the number is worth it. No budget setting does that for you. The tool your team built didn't get worse. Its cost went from invisible to visible, so treat it like any other line item.
