If someone in your office — an ops lead, a precon coordinator, whoever had a Copilot seat and enough curiosity to try agent mode — used GitHub Copilot to build an internal tool like an RFI-log watcher, a submittal tracker, or a vendor cut-sheet scraper, that tool is no longer running on a flat monthly fee. GitHub moved Copilot Chat, agent mode, code review, and the CLI to metered AI-credit billing on June 1, 2026, and the first full billing cycle showed some users' costs jumping 10 to 50 times over what they paid in May. The fix isn't to shut the tool off — it's to find out what it actually costs and put a cap on it before the next invoice.

## What actually changed in GitHub Copilot's pricing?

Per-seat subscription prices didn't move — Pro is still $10 a month, Pro+ is $39, Business is $19 per user, Enterprise is $39 per user. What changed is what that seat price covers. Inline code completion and Next Edit Suggestions stay unlimited on every plan. Everything that does multi-step work — Copilot Chat, agent mode, code review, and the Copilot CLI — now draws from a monthly pool of AI Credits billed at each underlying model's published API rate, roughly one credit per cent. Individual Pro gets 1,500 credits a month, Pro+ gets 7,000, Business gets 1,900 per user, Enterprise gets 3,900. None of it rolls over to the next month.

## Why does this hit a construction office that doesn't employ developers?

Because you don't need a developer on staff for this to matter — you just need one person with a Copilot seat and the habit of reaching for agent mode instead of doing something by hand. A lot of the small tools quietly running inside GC and sub back offices — an RFI-status watcher, a submittal-log monitor, a spreadsheet cleanup script, a basic estimating helper — got built exactly that way: someone with access tried agent mode once, it worked, and it's been running unattended ever since. Those are the workflows that draw hardest on the metered pool, because agent mode makes many model calls per task instead of one, and nobody is watching each call the way a developer watches each line of code they write.

## How much did costs actually jump?

Enough that GitHub's own community forum filled up with complaints within days of the June 30 close of the first full cycle. One developer logged a single agent-mode request burning 822 credits — 54% of a month's Pro+ allotment — on what they described as a small project. Others reported draining an entire 7,000-credit Pro+ pool in a couple of hours of agentic work, or projecting full depletion within 48 hours at normal usage. Outside reporting on that first cycle put dollar terms on it: accounts projecting monthly bills jumping from roughly $29 to $750, and from $50 to $3,000, once usage was priced at metered rates instead of the old flat subscription. The pattern is consistent across every report: code completion isn't the expensive part. Letting an agent run multiple steps without you supervising each one is.

## GitHub Copilot plans and AI credits, compared

| Plan | Monthly price | AI Credits included | Rollover |
|---|---|---|---|
| Individual Pro | $10/mo | 1,500 credits | No |
| Individual Pro+ | $39/mo | 7,000 credits | No |
| Business | $19/user/mo | 1,900 credits/user, pooled at org level | No |
| Enterprise | $39/user/mo | 3,900 credits/user, pooled + cost-center caps | No |

Code completion and Next Edit Suggestions are unlimited on every plan above and don't draw from the credit pool. Chat, agent mode, code review, and the CLI all do.

## Can you cap the spend before it surprises you?

Partially, and GitHub has been adding controls since the rough first cycle. In July, session-level limits shipped for the Copilot CLI and SDK, letting a single interactive session cap itself at a set number of credits before it stops — useful for a one-off automation run, though it's a soft cap, since usage on a request already in progress isn't known until that request finishes. For a firm managing several seats under Business or Enterprise, the more useful control is an org-level budget: GitHub's billing settings let an admin set a spending limit for the organization or for specific users, with the option to block further usage once the budget is hit instead of letting it roll into overage charges automatically. Enterprise customers also got cost-center-level caps in July, so a specific team or project's AI spend can be capped independently of the rest of the org's pool.

None of these controls existed when the first billing cycle closed at the end of June, which is part of why that cycle's bill shock caught so many users off guard. If your firm's Copilot seats are still running on default settings, this is the fix: go into Settings → Billing → GitHub Copilot, check what's actually consuming the credit pool, and set a hard cap before the next cycle closes rather than after.

## Should you keep the internal tool, rebuild it, or kill it?

That depends on what the tool is actually worth to your office, and metered billing is the first time you've had a real number to compare against. Run one full billing cycle with a spending cap in place and look at what it actually cost — not the vendor's example calculation, the real number for your usage. If an RFI-log watcher costs $40 a month to run and saves a coordinator two hours a week, that's an easy keep. If a submittal-tracking automation is burning hundreds of dollars because it re-scans every document on every run instead of only new ones, that's a design problem worth fixing before you decide the tool itself isn't worth it.

For firms with heavy, predictable usage, there's a longer-term alternative worth knowing about even if it's not a near-term fix: [Thinking Machines Lab released Inkling](https://thinkingmachines.ai/news/introducing-inkling/), a 975-billion-parameter model, under a free commercial license in July 2026, which means a firm with the engineering resources to self-host can run agent-style automation without per-token metering at all. That's a real option for a software vendor sizing infrastructure — it's a much bigger lift for a five-person back office than switching to a spending cap and a monthly review.

The honest bottom line: the internal tool your team built didn't get worse. Its cost just went from invisible to visible. Treat it like any other line item — know what it costs, cap what it can cost, and decide if it's still worth it with real numbers instead of a flat subscription hiding the answer.
